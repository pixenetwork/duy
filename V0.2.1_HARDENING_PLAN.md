# Pixel Network Foundation v0.2.1 — Hardening Plan

## Goal

Close the independent v0.2.0 audit findings without redesigning the approved Enhanced-only architecture or adding new product scope.

## Work completed

1. Require every file shipped under `resources/pixel_ui/web/dist` to be covered by the resource manifest's `files {}` declarations.
2. Return clean validator failures for missing production entry files and verify each content-hashed asset against its filename.
3. Bound diagnostics by recursion depth, table breadth, total node budget, key/string/message/name length, and final encoded output size.
4. Expand sensitive-key redaction for common short aliases without broadly matching harmless words.
5. Replace readiness and diagnostics regex checks with Lua 5.4 behavioral tests that execute the shipped code under mocked FiveM primitives.
6. Add a checksummed vendor manifest that documents and validates the extracted React module IDs and ReactDOM-to-React alias.
7. Make `dist` replacement transactional and reject any TypeScript compiler version other than the lockfile/package pin.
8. Add bounded readiness recovery through `RequestCapabilities` and log exhausted handshake cycles.
9. Update release reports, prompts, documentation, and changelogs.
10. Run complete verification, deterministic rebuild comparison, fault injection, and ZIP integrity checks.

## Non-goals

- No legacy FiveM, ESX, QBCore, pma-voice, or Mumble compatibility.
- No Character, Clothing, Admin, Inventory, Phone, Banking, or Housing feature work.
- No claim of live FiveM Enhanced certification until staged in an actual Enhanced server/client environment.
